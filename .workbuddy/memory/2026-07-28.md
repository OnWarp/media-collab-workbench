## 重构：云端存储从 Durable Object 迁移到 Cloudflare D1（用户选定「迁移到 D1」）

- 动机：需要持久化关系型存储且避免 Durable Object 单实例串行化的局限，改用 D1（SQLite）。
- `worker.js` 全量改写为 D1 访问（`env.DB`），新增 `jget/jset/all/one/run` 辅助与 `topicView/msgView/publicUser/esc`，**API 契约保持不变**（前端无需改动）。
  - 移除 Durable Object 类 `AppState` 与 `state.storage` 路由；布尔字段用 INTEGER 0/1，JSON 数组/对象字段（referenceLinks、mediaLinks、series、favoritedBy、rejectedNotes、traffic、topicIds、referenceVideos）以 TEXT 存储。
  - `logs` 集合云端移除（详情接口始终返回 `logs:[]`）；`messageRecycle` 并入 `messages` 的 `deleted=1` 软删除机制。
- 新增 `migrations/0001_init.sql`：八表 users/sessions/topics/comments/materials/messages/weeklySettlements/announcements + 公告单例种子 id=1 + 索引。已在本地 SQLite 验证可执行。
- `wrangler.jsonc`：`d1_databases` 绑定 `DB` → `media-collab-db`，`database_id` 用占位符 `__D1_DATABASE_ID__`（CI 自动注入）；移除 `durable_objects`/`migrations`。`wrangler.jsonc.example` 同步更新。
- CI（`.github/workflows/deploy-worker.yml`）增加步骤：幂等 `wrangler d1 create`（**不传 --config** 以避免占位符触发校验失败）→ `wrangler d1 list --json | jq` 取 uuid 注入临时 `wrangler.jsonc` → `wrangler d1 execute ... --remote --file=./migrations/0001_init.sql`。
- 新增 `scripts/migrate-to-d1.mjs`：把本地 `data/db.json` 灌入 D1，生成 `migrations/_migrated_seed.sql`（已 gitignore）。
  - **关键坑**：旧 `server.js` 用 scrypt 存密码，D1 worker 用 PBKDF2(21万次)，哈希不兼容 → 迁移脚本会把账号密码重置为统一临时密码（--password 指定或自动生成），登录后需改密。
  - INSERT OR IGNORE（announcements 用 REPLACE）保证幂等；跳过 logs 与 messageRecycle。已用 Python sqlite3 验证两 SQL 文件可正常执行。
- 文档：`README.md`、`WORKERS_DEPLOY.md` 全面改写为 D1 架构描述。
- 已本地提交 `01779cb`。仍需用户自行 `git push origin main`（沙箱无 GitHub 凭据）并配置 Secrets（API Token 需含 D1 编辑权限）。
