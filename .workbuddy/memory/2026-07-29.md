## CI 部署失败根因修复：worker.js → worker.mjs + 工作流加固

- **根因**：`worker.js` 用 ESM `export default {}`，但仓库无 `"type":"module"`（server.js 是 CommonJS），导致 wrangler 把入口误判为 CommonJS，部署时 SyntaxError 退出 1。旧 CI 的 `node --check` 复制成 `.mjs` 校验，反而掩盖了该问题。
- **修复**：`worker.js` 重命名为 `worker.mjs`（显式 ESM，绕开 package.json 的 CJS 默认），`wrangler.jsonc(.example)` 的 `main` 指向 `worker.mjs`，语法校验改为直接 `node --check worker.mjs`。Windows 文件锁导致旧 `worker.js` 无法删除，已 `git rm --cached` 并加入 `.gitignore` 忽略遗留文件。
- **CI 工作流加固**：
  - 部署步骤 `set +e` 捕获并打印 `wrangler deploy` 真实输出与退出码，失败时显式 `exit $CODE`（不再被 `bash -e` 吞错）。
  - 自动建管理员改为必须同时具备 `BOOTSTRAP_TOKEN` + `ADMIN_USERNAME` + `ADMIN_PASSWORD`；缺 `BOOTSTRAP_TOKEN` 仅告警跳过（避免 403）。`BOOTSTRAP_TOKEN` 缺失时会触发 `::warning::`（建议 `openssl rand -hex 32`）。
- 文档 README/WORKERS_DEPLOY/migrate 脚本中 `worker.js` 引用全部改为 `worker.mjs`。
- 已本地提交 `edd543b`（rename + CI 加固，8 文件）。`worker.mjs` 经 `node --check` 通过；`deploy-worker.yml` 经 pyyaml 校验 14 步均有效。
- **推送阻塞（未完成）**：本沙箱无 GitHub 写凭据——仓库为 public（匿名读可，`ls-remote` 成功），但 `push` 报 `could not read Username`（GCM 无可用写令牌且会卡交互提示；`gh` CLI 未装；env 无 GITHUB_TOKEN）。需用户在本地 `git push origin main`，或提供 GitHub PAT 后由我推送触发 CI。
